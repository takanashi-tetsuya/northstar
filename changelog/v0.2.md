# Northstar 0.2 development changelog

- **Status:** Release candidate prepared
- **Package version:** `0.2.0`
- **Baseline Git commit:** `998396915ab38a9deadf47ae871be561e11f7ef2`
- **Baseline package/schema:** `0.1.0`, migrations `0001`–`0013`
- **Current migration maximum:** `0128_mix_capacity_authorities.sql`

This document records the complete repository change set from the previous Git
commit to the current release candidate. Cargo, Compose, OCI, backup and
OpenAPI metadata consistently identify this pre-1.0 build as `0.2.0`.
Version `1.0.0` is deliberately reserved until one exact artifact and target
environment satisfy every applicable production qualification gate in
[the release checklist](../docs/RELEASE_CHECKLIST.md).

Protocol claims are normative only in [XEP_MATRIX.md](../XEP_MATRIX.md).
Unresolved compromises and qualification gates are normative only in
[docs/KNOWN_ISSUES.md](../docs/KNOWN_ISSUES.md). `Core` means Northstar's
documented bounded profile has automated local evidence; it does not mean that
every optional clause of a standard or every third-party implementation has
been qualified.

## Repository delta

Compared with the baseline commit, the current staged release candidate
contains:

- 540 changed paths: 416 added, 121 modified, two renamed and one deleted;
- 344,442 inserted and 7,861 removed lines;
- 157 Rust source files, up from 52 in the baseline;
- 127 database migrations, up from 13, covering `0001`–`0128` with `0021`
  intentionally reserved;
- 92 separately classified RFC/XEP profiles, replacing 30 matrix rows that
  represented 31 standards;
- 136 script changes, 28 documentation changes, 20 Web-client changes, 21
  deployment changes, 19 vendored third-party/provenance files and 13 fuzzing
  files.

The scale of this delta reflects a server-wide protocol, security, persistence
and operations redesign rather than an incremental feature patch.

## Release-candidate CI and registration corrections

- Added a fail-preserving CI command wrapper that captures each isolated
  fixture's output, redacts common credential forms, and promotes only the
  relevant failure lines into a named GitHub check annotation. Protocol,
  database, MIX, federation, component and XEP-0487 jobs now identify the exact
  failing fixture without requiring privileged or adversarial local replay.
- Made automatically selected federation fixture ports robust against the
  kernel immediately returning the same just-released ephemeral port to two
  consecutive probes. Automatic selection retries up to a bounded limit;
  duplicate caller-provided overrides continue to fail closed.
- Corrected durable C2S delivery ownership when XEP-0198 is not active. Counted
  messages, presence and IQ stanzas legitimately remain transport-owned until
  a successful socket write; the previous debug assertion could panic the
  WebSocket connection actor even though the durable fence was following the
  intended write-boundary path. A pure ownership matrix test covers active SM,
  inactive SM, non-durable stanzas and non-counted SM control elements.
- Split upload core and upload-administration PostgreSQL fixtures into separate
  random schemas because their intentionally different capacity policies are
  immutable after binding. Cleanup now attempts every schema even after an
  individual drop failure and verifies that none remain.
- Aligned the authentication publication/expiry-cleanup concurrency test with
  the production routine's `FOR UPDATE SKIP LOCKED` contract. Cleanup must
  complete without deleting the publication-locked lease, then reclaim it only
  after the exact publication transaction releases its lock.
- Corrected federated MIX-PAM leave completion. The remote channel returns the
  direct, empty `<leave xmlns='urn:xmpp:mix:core:1'/>` success required by the
  core protocol; the local completion path previously sent every one-element
  result through the join parser and timed out after rejecting that valid
  payload. Leave parsing remains strict about namespace, attributes, children
  and non-whitespace text.
- Changed the durable MIX/PAM worker's shutdown boundary: cancellation stops
  new claims but drains the current bounded batch through acknowledge, retry or
  defer. Previously, dropping a claimed delivery future could retain the

- Made the XEP-0191 integration assertion independent of the serializer's

  both signals reach the connection through the same cancellation token.
  Orderly process shutdown is now a debug lifecycle event and no longer
  increments `federation_failures_total`; an actual CRL-driven cancellation

- Added migration `0125_registration_control_fail_closed.sql`. Account
  registration now treats a missing durable `registration_closed` authority row

- Preserved the identity of retracted archived messages. A tombstone now

  claims, extension-bearing claims and malformed authorities. At the personal
  MAM output boundary, Northstar also replaces any same-account claim with the
  immutable `ArchiveRow.id`; this repairs already stored legacy tombstones and
  guarantees that the MAM `<result id>` and account authority ID agree without
  deleting valid provenance assigned by another authority.
- Made the concurrent PostgreSQL PoW capacity fixture expire the exact UUID
  returned by its successful account challenge before testing restart-safe
  slot reuse. Its previous global `ORDER BY ... LIMIT 1` could expire an active
  challenge left by another test in the shared random schema, leaving the
  intended actor at capacity and producing a false failure. Because this same
  case deliberately reaches the 50,000-row global ceiling, it now records and
  deletes only its issued challenge UUIDs and randomized `key_id` filler rows,
  asserts the exact cleanup count, and preserves any pre-existing fixture rows
  before the next exact test process reuses the schema.
- Closed the dollar-quoted PL/pgSQL function used by the federation no-store
  persistence probe. The missing `$$;` made PostgreSQL reject the fixture's
  trigger setup as an unterminated function body before the live-route assertion
  ran; schema isolation and ownership were not involved.
- Moved the federation fixture's schema selection to connection-level
  `PGOPTIONS`. Combining `SET search_path` with a scalar `SELECT` made psql
  return `SET\n0`, which the strict zero-persistence assertion correctly did
  not accept even though all durable counts were zero.
- Separated OMEMO 2/SCE envelope validation from the server's XEP-0334 storage
  decision. A payload message must still include exactly one direct `<store/>`
  marker as required by XEP-0420, but an additional `<no-store/>` no longer
  causes a false `not-acceptable`: the privacy-preserving policy suppresses
  S2S outbox, MAM and offline persistence while allowing the already
  authenticated live federation route. A failed volatile route now emits a
  domain-only debug diagnostic without exposing stanza content.
- Replaced the protocol fixture's stale global `archived_stanzas == 4`
  constant with an exact relative ownership assertion. The measured flow adds
  one deduplicated Alice self-message row which survives as a content-free
  retraction tombstone, the separately auditable retraction action, plus sender
  and recipient projections for each of the offline and paginated encrypted
  peer messages, for a six-row delta over the pre-flow baseline. The fixture
  also verifies the tombstone and action shapes directly.
- Updated the session-identity PostgreSQL fixture for the migration 0108
  capability boundary: its synthetic admin command session now includes the
  mandatory 32-byte `bearer_hash` instead of failing before identity
  canonicalization is exercised.
- Updated the durable MUC-invitation failure fixture with the retention policy
  and legal-hold relations parsed by the real admission CTE. The test now
  reaches its deliberate insert fault and proves affiliation/spool rollback
  instead of stopping at a missing fixture relation.
- Made the MIX runtime acceptance boundary deterministic without changing the
  product's delivery policy. A reverse-direction presence first proves Bob's
  verified MIX capability route and drains earlier per-recipient outbox heads;
  an Alice IQ barrier then separates synchronous group-message admission from
  durable fan-out and exposes any stanza error. The group-message assertion uses
  the fixture's normal deadline rather than hiding a latency regression behind
  the capability-correlation timeout; timeout errors include pending frames,
  and both console and fixture-owned rolling logs are emitted before cleanup.
- Replaced the MIX delivery capacity-release lock coupling at its database
  boundary. Migration 0126 changes recipient/event delete triggers from
  fail-fast capacity-bucket updates to independent write-once release facts
  that admission later consumes transactionally.
  An ACK now deletes only its exact fenced recipient and journals that row/byte
  credit in one transaction without acquiring the admission fence, a shared
  capacity row or the causal parent event. This removes the normal `55P03`
  failure without moving the hotspot to the parent of a large broadcast.
  `FOR UPDATE SKIP LOCKED` GC continues to delete empty event templates and
  sequence authorities as a maintenance optimization; it no longer supplies
  the correctness boundary for later admission.
- Capacity admission consumes release facts with one
  set-based `DELETE ... RETURNING` aggregation under a schema-specific global
  fence derived from the capacity relation identity. Migration 0128 first runs
  a complete orphan-event reclamation and release-ledger fold in a separately
  committed owner-held phase. Applying credits,
  checking the 100,000-row/256-MiB limits and reserving new capacity share one
  producer transaction. A capacity rejection therefore cannot roll back the
  reconciliation required to escape a false-full state. A completion that
  commits after reconciliation is a later linearization event and is visible
  to the following admission; correctness does not depend on a GC page size,
  fixed retry count or maintenance cadence. All 18
  delivery-producing `MixService` operations now share one clone-safe FIFO
  gate acquired before PgPool checkout. The corresponding database transaction
  then takes a blocking schema-local admission fence as its first SQL statement
  and carries a typed proof through every enqueue/reservation helper. Ordinary
  same-process contention therefore waits fairly without consuming the pool or
  being misreported as capacity exhaustion, while cross-process writers wait
  before owning any channel, event or sequence lock. Actual ceiling rejection
  still rolls the complete mutation back. The release table is read-only to
  the runtime role: owner-held SECURITY DEFINER triggers are its only INSERT
  path and an allowlisted drain capability is its only DELETE path. The drain
  validates underflow inside PostgreSQL, so a caller cannot commit a partial
  credit application. Static architecture checks retain migration 0120's
  event-leading `(event_id, recipient_jid)` unique index used by drain and
  orphan GC. Dead-letter recovery locks an
  existing parent event `FOR UPDATE` before reintroducing its recipient, so it
  linearizes with event GC instead of attempting a `FOR SHARE` to write-lock
  upgrade. If the event is
  absent, concurrent requeues use `INSERT ... ON CONFLICT DO NOTHING RETURNING`
  to elect one physical template creator; only that transaction reserves the
  event bytes, while losers lock and verify the winner before reserving their
  independent recipient. Normal fan-out also sorts recipients by canonical JID
  before its sequence UPSERT, eliminating cross-channel A-to-B/B-to-A lock
  inversion when channels list the same recipients in different participant
  order.
- Removed the temporary completion retry/timing policy after eliminating its
  underlying capacity-lock dependency. One exact ACK transaction either
  commits the recipient deletion and release fact or leaves the durable
  90-second lease intact. Pool exhaustion, I/O failure, query cancellation,
  database restart and commit uncertainty therefore return to the existing
  at-least-once recovery path; the stable authoritative stanza ID is the
  recipient deduplication key.
- Added an isolated PostgreSQL regression that deliberately holds the producer
  capacity fence while a leased recipient ACK commits, then stages and rolls
  back complete reconciliation before committing it. The test proves the ACK
  does not wait on or fail with the producer fence, rollback restores the orphan
  event/release fact/ledger together, and committed reconciliation returns to
  the exact pre-test capacity totals without worker timing.
- Migration 0126 is deliberately a stopped-writer cut-over. Operators must stop
  every pre-0126 runtime, delivery worker and maintenance writer before applying
  it; pre- and post-0126 writers are not permitted to run concurrently.
- Replaced XEP-0198 resume-contention polling with a transactionally ordered
  event broker. Migration `0127` gives every durable SM row a monotonic
  `state_version`, advances it on every state transition, and emits a
  commit-time notification containing only schema/session/version. One
  supervised, single-connection `PgListener` per process feeds session-scoped
  watch slots and advances a global generation across reconnects. Resume first
  subscribes and immediately repeats the authority query, then waits only for
  an exact event, exact local-route removal, new-connection cancellation or the
  database-returned retry boundary. Pending waits no longer retain a maximum
  snapshot-memory reservation. Exact local live owners are cancelled through
  their matching connection/session incarnation; cross-node completion remains
  database-authoritative. Each delivered notification also advances a one-shot
  local sequence; its retained `state_version` is an optimization, never a
  deduplication authority, so a stale/forged high value cannot suppress a later
  real edge. Explicit participant RAII and Arc-identity removal
  close subscriber-construction/drop races without accumulating stale slots.
- Migration `0127` is a stopped-writer capability cut-over. It replaces the SM
  claim projection and exact session catalog health function, adds two
  owner-only private trigger capabilities, denies runtime direct access to
  `state_version`, and preserves the existing runtime claim signature. The
  canonical capability manifest, role attestation, migration ledger and static
  gates include the new identities and checksum.
- Corrected migration `0127` to use PostgreSQL's unqualified
  `LEAST`/`GREATEST` special expressions. Treating them as schema-qualified
  `pg_catalog` functions prevented a fresh database from parsing the function;
  the migration ledger and both SQL static guards now assert the valid form.
- Migration `0128` removes two capacity outcomes that could previously be
  mistaken for legitimate overload. MIX delivery admission now runs complete
  orphan-event reclamation and release-journal folding in a separately
  committed owner-held phase before it opens the producer transaction. A later
  hard-cap rejection cannot roll that reclamation back and reproduce the same
  false-full state; the producer drains any release facts committed in the
  intervening window under the same schema-local database fence.
- The database-role quoted-schema replay now mirrors SQLx migration by
  migration: ordinary files run in their own transaction, while explicit
  `-- no-transaction` concurrent-index files remain outside one. This keeps
  the atomic `LOCK TABLE` cut-overs in `0126` and `0128` meaningful while still
  proving the complete chain against a schema containing spaces and quotes.
- Remote MIX-PAM admission no longer combines `COUNT(*)` with a non-waiting
  advisory lock. Owner-maintained global and per-account counters are updated by
  insert/delete triggers under a fixed account-row → global-counter → user-
  counter order. A clone-shared FIFO service gate is acquired before PgPool
  checkout, so one process contributes at most one cross-process database
  waiter without converting ordinary contention into a rejection.
- Runtime can neither write the counter tables nor directly insert/delete the
  PAM operation journal. The insertion capability re-proves the enabled account
  identity and verifies the exact pending membership and durable S2S outbox
  projection in the same transaction before creating the journal row. Bounded
  worker pruning remains an optimization; producer admission first commits a
  complete retention-eligible reconciliation, while unresolved late-result
  authority remains deliberately charged. Startup compares both counter
  projections against the journal and fails closed on any drift.
- Made the XEP-0115 capability side effect monotonic with explicit XEP-0405
  presence. Its conservative empty available projection now inserts only when
  the exact participant resource has no current presence, with the absence
  check serialized by the channel row lock. A delayed capability worker can no
  longer replace a newer client-authored `<show>`, status or extension payload.
- Replaced the caps queue/cache ownership model with one authoritative
  observation for every accepted available full JID. A local observation is
  owned by its exact `(connection_id, generation)`; a federated observation is
  owned by `(connection_id, observation_id)`, so repeated advertisements on the
  same authenticated stream cannot create an ABA match. Per-resource gates
  order available, unavailable, disco correlation and final PEP/MIX effects,
  and connection teardown compare-removes only observations owned by that
  incarnation.
- Reduced the verified semantic projection to the two MIX feature bits and the
  complete `+notify` node list actually consumed by server behavior. The list
  is not silently truncated: it is bounded by the existing 64-KiB disco payload
  and 512-child parser limits. Current observations retain the projection
  independently of the byte-bounded raw/summary cache, so cache expiry or
  eviction can only cause a later query or disco-proxy miss, never a negative
  PEP/OMEMO/MIX decision.
- Moved asynchronous correctness into observation-owned pending/running effect
  bits. The bounded work queue stores only deduplicated wake hints; saturation,
  a failed effect or worker restart leaves semantic work discoverable from the
  observation. Independent local/federated queues alternate admission so a
  remote flood cannot starve local OMEMO/PEP initialization. Saturation/restart
  requests an immediate rescan, while failures wait for the earliest retained
  retry or pending-IQ expiry rather than a polling loop. Retry timestamps
  schedule retained work but do not decide whether it exists. Federated
  resource counts are explicit pre-routing admission policy and return
  `resource-constraint` when exceeded. Independent summary-memory pressure
  retains pending verification instead of accepting a truncated or negative
  capability result.

## Architecture and responsibility boundaries

- Introduced a domain-oriented application-service layer under `src/services/`
  for authentication, accounts, messaging, replay, Stream Management, roster,
  presence, privacy, blocking, MAM, MUC, MIX, PubSub, profiles, retractions,
  push, upload and administrator commands.
- Removed direct SQLx, `PgPool`, raw pool, database-authority and database DTO
  use from the protocol tree. Protocol handlers now own XML parsing,
  negotiation and stanza error mapping; services own authorization,
  transactions and side effects.
- Reduced `AppState` to nine public capabilities. Keyrings, stores, worker
  supervision, routing registries, semaphores and persistence capabilities are
  private.
- Added monotonic architecture checks. The current baseline is `AppState=9`
  and zero protocol-tree references to database authority, database domain
  models, `state.pool`, SQLx and `PgPool`.
- Added a supervised worker registry with unique identities, heartbeats,
  bounded restart backoff, critical/restartable classifications, readiness
  degradation and fail-fast behavior for security-authority loss.
- Split transport parsing, outbound delivery, password work, account-deletion
  recovery, retention, upload recovery, cluster security and asynchronous
  operation execution into dedicated modules.
- Replaced raw outbound XML string composition with typed stanza builders and
  validated fragments. Static heuristic gates keep the tracked raw-output
  baseline at zero across protocol, transport, federation, component and
  cluster code; this is a regression barrier, not a formal XML-injection proof.
- Added architecture, process-isolation, outbound-XML, runtime-migration and
  session-lifecycle regression gates.

## XML framing and transport security

- Reworked the existing balanced-depth scanner into a reusable, resource-bounded
  incremental XML entity framer with persistent scan state across transport
  fragments. It preserves the baseline handling of nested elements, quoted
  attributes, declarations, comments and CDATA while adding fragmented-UTF-8
  safety and transport integration.
- Preserved and regression-tested complete outer framing for nested forwarded,
  Carbon and MAM stanzas.
- Added resource ceilings for frame bytes, nesting, element count, attributes,
  start tags, declarations, negotiation and idle time.
- Added shared restricted-XML and top-level stanza validation before protocol
  dispatch.
- Added exact RFC 7395 WebSocket subprotocol/origin checks, text-only frames,
  bounded fragmentation, namespace validation and XML-close/WebSocket-close
  sequencing. Binary XML messages, invalid masks, RSV bits, opcodes and
  oversized frames fail closed.
- Added XEP-0124/XEP-0206 BOSH with keyed SID storage, an ordered two-request
  RID window, bounded out-of-order waits, byte-identical replay,
  request/response acknowledgements, optional `key`/`newkey`, pause/terminate
  behavior and explicit memory/session limits.
- Fixed legacy BOSH restart requests carrying the standards-valid `to`
  attribute.
- Added XEP-0478 stream byte and idle limits to applicable TCP, WebSocket, S2S
  and XEP-0288 paths. BOSH retains its HTTP/RID/inactivity limits.
- Hardened the existing mandatory STARTTLS C2S/S2S listeners and added Direct
  TLS C2S/S2S listeners with standard ports, SNI, ALPN, shared identity checks
  and bounded negotiation.
- Hardened incremental scan state against stale UTF-8 byte offsets. Each saved
  offset is checked before slicing, and standalone WebSocket messages reset
  only pending frame state at message boundaries.
- Fixed the reported `bosh_ws_framing` corpus panic caused by applying a stale
  cursor to the middle of a multibyte character. Production WebSocket code
  already terminated after the first framing error, so the corpus did not
  establish a remote whole-process DoS; parser totality and the fuzz gate were
  still corrected.
- Fixed two independent PubSub Atom notification-preview panics by truncating
  at a valid UTF-8 boundary instead of blindly calling

## Remaining deliberate and external boundaries

- S2S, XEP-0114 and XEP-0225 final transport remains at-least-once around the
  socket-write/database-completion boundary.
- XEP-0198 and BOSH acknowledgements prove a transport boundary, not UI display,
  application processing or user reading.
- XEP-0114's SHA-1 handshake is not transport encryption; use loopback, VPN,
  mTLS tunnelling or equivalent isolation.
- Federated MUC occupancy is not silently restored without verifiable remote
  ownership.
- `no-store`, presence, typing, Carbons and selected notifications remain
  volatile or best effort where persistence would violate semantics or create
  unbounded debt. `no-permanent-store` may use bounded temporary delivery state
  but is never retained in permanent MAM history.
- Anonymous-room history rejects real-sender filtering where it would become an
  identity oracle.
- TURN/media and mobile push data planes are separately deployed services.
- Capacity rejection, finite retention, dead letters and fail-closed readiness
  are intentional safety controls.
- OMEMO private keys and device trust stay at endpoints; submitted decrypted
  report text cannot be authenticated by the server.
- TLS reload affects future handshakes; existing sessions require reconnect,
  exact revocation or an operational drain.
- Only locally supplied signed/fresh CRLs are supported. OCSP and online
  AIA/CRL retrieval are outside the profile.
- Browser OMEMO continues to trust same-origin static-resource delivery, cannot
  provide true TLS-exporter SCRAM-PLUS and cannot prove secure JavaScript memory
  erasure.
- The server cannot meaningfully scan OMEMO-encrypted attachment plaintext. It
  validates ciphertext size, declared type, hash and storage integrity only.
- OMEMO transfer is a one-use device move, not escrow or general backup.
- Vendored browser WASM/JS is provenance-traced and hash-pinned but not yet
  source-to-byte reproducible.
- The S3 backend cannot precisely delete arbitrary noncurrent object versions;
  provider lifecycle and object-byte backup are required.
- Runtime database permissions are substantially reduced, but the runtime role
  still has broad DML over many mutable business tables outside account
  authority. Runtime and command URLs use distinct database roles but enter the
  same OS process, so full process compromise is not isolated by that split.
- Application checks cannot defend against a malicious database owner, lost
  KMS/HSM material or an untrusted WORM/backup administrator.
- The zero raw-output check is a static heuristic, not a formal proof against
  XML injection. The offline `pie.rs` specialist serializer is outside the
  complete runtime zero-baseline assertion.
- Protocol-to-database coupling is zero, but nine public `AppState`
  capabilities and broad runtime DML outside account authority remain
  architecture debt.
- Redis clustering is Experimental and is not consensus. Some cluster presence,
  typing, Carbon and notification state remains soft. Ordinary MUC groupchat is
  archived, but real-time cross-node fan-out has no per-recipient durable outbox
  and can lose live delivery during a Redis outage.
- Complex mixed MUC affiliation/role batches remain rejected until one atomic
  authorization/audience transaction can represent them.
- No manifest-driven resumable local-to-S3 migration utility exists yet.
- Restore rollback directories may contain plaintext and must be placed on an
  encrypted filesystem. Loss of backup-sequence or restore-floor state changes
  which lineage can be trusted; `development-legacy` remains an explicitly
  non-production unsigned compatibility path.
- A hard crash during restore can require manual journal diagnosis and
  resume/compensation.
- Historical canonical-identity collisions and archive rows without reliable
  direction require operator decisions; software cannot infer ownership or
  history safely.
- BOSH multi-stream sessions, general S2S multi-domain multiplexing, target
  piggybacking and pooled S2S streams remain unsupported and unadvertised.
- Multi-node failure testing, public federation, real components, broad client
  interoperability, provider recovery, target capacity/soak and independent
  security review remain external qualification gates.
