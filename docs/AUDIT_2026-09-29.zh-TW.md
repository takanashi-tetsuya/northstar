## 確認的發現

### A1 — P2：管理介面忽略 `next_cursor`，超過第一頁的資料無法操作

位置：[web/app.js:134](../web/app.js#L134)、[web/app.js:257](../web/app.js#L257)、[web/app.js:315](../web/app.js#L315)。後端契約見 [src/api/admin.rs:59](../src/api/admin.rs#L59)。

`loadAdmin()`、`loadSessions()`、`loadRooms()`、`loadOperations()` 只載入一次資料並渲染回傳陣列，沒有保存／使用各列表的 `next_cursor`。目前只有 operation 的 targets 子列表實作後續分頁。

| 列表 | 後端預設／介面指定頁大小 | 影響 |
| --- | ---: | --- |
| 使用者 | 100 | 第 101 個以後的帳號無法透過列表停用或調整權限 |
| 在線會話、房間 | 100 | 後续資源無法從列表斷線或刪除 |
| 舉報、邀請碼 | 25 | 舊舉報／邀請码被靜默隱藏 |
| 管理操作 | 25 | 舊操作無法從列表發現；已知 ID 的查詢仍可使用 |

**重現：**用 Node VM 執行現有 `web/app.js` 中未修改的函式，API mock 回傳 `users=101`、第一頁 100 列及非空 cursor。實際只渲染 100 列，所有列表總共發出 9 次請求，後續 cursor 請求為 0。這是實際執行前端函式的測試，並非真實瀏覽器 DOM E2E。

**建議：**每個列表保留 cursor，提供「載入更多」／下一頁及明確的未完整載入提示；以超過頁大小的資料驗證最後一頁可達。避免以無上限自動抓完所有資料取代分頁。

證據：重現程式（私有證據：`target/audit-2026-09-29/repro-admin-pagination.cjs`）、輸出（私有證據：`target/audit-2026-09-29/repro-admin-pagination.log`）。

### A2 — P2，本機環境：`.env` 與 `.env.bak` 含憑證且模式為 `0755`

兩份檔案皆含非空資料庫密碼及 bootstrap 管理員密碼設定；`.env` 另含 migrator 連線設定。審計只記錄設定鍵、是否有值及權限，沒有記錄密碼內容。

`stat` 顯示兩份檔案皆為 `0755`，group／other 有讀取權。任何同時具備父目錄穿越權限的本機身分都可能讀取它們。父目錄另有 ACL，因此不能僅憑檔案模式宣稱所有系統帳號當下均可讀取。

**範圍：**目前設定使用 localhost；這是本機開發環境風險，不是已證實的網路洩漏或 Git 洩漏。受版本控制的敏感檔案掃描通過，兩者均未因本次審計加入版本控制。

**建議：**設定檔與必要備份改為 `0600`，確認父目錄 ACL；移除不必要的明文備份。若曾讓不受信任身分取得讀取權，再輪換相應憑證。本次依 audit 範圍保留原檔及權限。

證據：不含秘密值的中繼資料（私有證據：`target/audit-2026-09-29/local-config-metadata.json`）。

### A3 — P2，原型上線前：RPC 空允許名單隱含放行所有有效工作負載

位置：[crates/foundation-service-runtime/src/authz.rs:154](../crates/foundation-service-runtime/src/authz.rs#L154)。

`RpcMethodPolicy::new()` 建立空的 `allowed_workload_services`，`register()` 接受該 policy；授權時只有在名單非空才檢查呼叫者是否在名單內。漏寫 `.allow_workload_service(...)` 因而變成隱含 wildcard。scope／role 條件也可以為空。

**重現：**註冊 `admin/Revoke`，不加入任何允許身分；使用有效且未列名的 `unlisted-service` 工作負載、無使用者 principal 呼叫 `authorize()`，結果為 `allowed: true`。

**影響邊界：**目前搜尋到的 `AuthorizationRegistry` 使用處為 foundation 的測試／介面，沒有確認它接入正式單體服務的請求路徑。專案亦將分散式微服務標為 prototype。因此這是原型授權預設值的風險，不能描述為現有正式管理 API 已可被任意呼叫。

**建議：**註冊時拒絕空允許名單，或令空名單表示拒絕所有人；若確需全體工作負載可用，要求明確的 opt-in API。加入空名單和遺漏授權設定的負面測試。

證據：最小重現（私有證據：`target/audit-2026-09-29/repro-empty-rpc-allowlist.rs`）、實際輸出（私有證據：`target/audit-2026-09-29/repro-empty-rpc-allowlist.log`）。

### A4 — P2，測試覆蓋：MIX 原子性回歸測試因 XML 引號假設而穩定失敗

位置：[src/db/mix_mam_tests.rs:901](../src/db/mix_mam_tests.rs#L901)。相關執行入口：[scripts/mix-mam-db-wsl.sh:12](../scripts/mix-mam-db-wsl.sh#L12)。

測試 `federated_mutation_result_and_outbox_share_the_authority_transaction` 以字串搜尋 `type="result"` 和 `channel="..."`。目前結構化 XML builder 產生 `type='result'` 與單引號屬性，因此第一個比較即失敗，後面的精確重試／不得重複執行斷言不會執行。

**重現：**在兩個全新 PostgreSQL schema 明確執行該 ignored test，兩次均以 exit 101 在同一行失敗。第二次讀回 `mix_federated_iq_results.response`：XML 可解析、IQ type 為 `result`、子元素為 `{urn:xmpp:mix:core:1}create`、channel 屬性存在、channel 資料列只有 1 筆。這支持「測試的序列化假設失效」，不足以宣稱完整原子性驗證已通過。

此測試標為 `#[ignore]`；一般 workspace 測試不會執行。現有 `mix-mam-db-wsl.sh` 明列的兩個測試不包含它；MIX family 腳本亦未選中此項。審查到的既有執行入口沒有覆蓋此精確測試。

**建議：**用 XML parser 驗證 namespace、element、attribute；對「精確重播」另保留 byte-for-byte 斷言。將該測試加入受 CI 執行的資料庫 suite，並檢查預期執行數，避免 ignored 測試新增後無人執行。

證據：第二次失敗日誌（私有證據：`target/audit-2026-09-29/verified-db-2.log`）、資料庫回覆驗證（私有證據：`target/audit-2026-09-29/mix-assertion-evidence.json`）。

### A5 — P3：部分資料庫腳本的 schema 管理與 Rust 測試連到不同埠

位置：[scripts/retention-db-wsl.sh:11](../scripts/retention-db-wsl.sh#L11)、[scripts/s2s-db-wsl.sh:68](../scripts/s2s-db-wsl.sh#L68)。同類問題也存在於部分 identity 腳本；migration-upgrade 腳本則將 CLI 與 URL 埠均寫死。

本次獨立 PostgreSQL 使用隨機 loopback 埠 `35845`。腳本中的 `psql` 遵守 `PGPORT` 並在該埠建立 schema，但 `TEST_DATABASE_URL` 寫死 `127.0.0.1:5432`。兩個未修改腳本分別以 `PoolTimedOut` 失敗。已確認当時 5432 沒有服務，未觸及既有資料庫。

**交叉驗證：**將腳本複製到審計暫存目錄，只替換固定埠並固定原始 repository 路徑；retention、S2S 以及相關 identity 測試即通過。這些通過結果明確標為「port-adapted」，不能冒充原始腳本通過。原始檔沒有改動。

**建議：**統一由一份 connection configuration 產生 `psql` 參數與 SQLx URL，保留隨機 schema 及專用 database 限制；加入非 5432 埠的腳本回歸。

證據：retention 原始失敗（私有證據：`target/audit-2026-09-29/db-retention.log`）、S2S 原始失敗（私有證據：`target/audit-2026-09-29/db-s2s.log`）、調整後結果（私有證據：`target/audit-2026-09-29/adapted-db-results.json`）、最小調整差異（私有證據：`target/audit-2026-09-29/port-adapted/retention-db-wsl.sh.diff`）。
