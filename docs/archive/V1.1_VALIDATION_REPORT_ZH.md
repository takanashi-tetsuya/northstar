# Northstar v1.1 功能验收、修复与审计报告

> **Historical snapshot — 不得作为当前 backlog 或能力清单。** 本文只记录 2026-08-25 当时的代码、声明核验与测试结果；后续实现已经使其中若干“未解决”结论失效。当前事实必须以实际代码/数据库 migration、根目录 `XEP_MATRIX.md`、`docs/KNOWN_ISSUES.md`、`docs/ARCHITECTURE.md` 和 `docs/PRODUCTION_OPERATIONS.md` 为准。本文不得覆盖这些当前来源，也不得仅凭本文重新建立开发任务。

审计日期：2026-08-25
审计对象：当前工作区 `rust-xmpp-server 1.1.0`、`changelog/v1.1.md` 所述增量以及相关部署/测试文件
结论等级：**可进入受控 staging；不能据此宣称已经通过独立安全认证或适合无监督公网生产**

## 1. 执行摘要

Gemini 提交的 v1.1 不是可直接验收的完成品。初始版本存在重复 migration 编号、Redis 被错误视为必需依赖、generic PubSub 授权与所有权缺口、Direct TLS/S2S 回包和队列丢失问题、roster version 不完整、MUC MAM 隐私边界、注册 PoW 实际为零工作量、运行时注册关闭可被 XMPP 路径绕过，以及管理踢线只删除索引但不关闭 socket 等问题。原 changelog 中的 “Full implementation”“full MUC MAM”“federated generic PubSub”“production-ready enterprise”“100% test coverage” 均不成立。

本轮已对上述问题进行修复或明确降级为 Partial/Experimental，并重写英文主 README、繁体中文 README、XEP 矩阵、已知问题、v1.1 changelog、OpenAPI 及 Redis 架构文档。网页端语言包按要求未在功能开发期间更新；仅执行现有语言包静态校验。

## 3. 本轮主要修复

### 3.1 数据库与配置

- 删除重复的 `0010` migration，新增唯一的 `0014_pubsub.sql`、`0015_roster_version.sql`、`0016_muc_mam_sender_index.sql`。
- Redis 改为未配置即可正常运行的选项；单机是受支持默认模式。
- 新增并校验 Direct TLS/S2S TLS 默认端口 5223/5270、contact URI、STUN/TURN、DNS override 和 `SERVER_NAME`。
- 包版本统一为 `1.1.0`，许可证元数据保持 `AGPL-3.0-only`。
- 全库清空默认关闭，只有 `ENABLE_DESTRUCTIVE_ADMIN=true` 才开放。

### 3.2 Generic PubSub

- 建立 node/item/subscription/affiliation 持久模型与约束。
- create、discovery、atomic multi-publish、generated ID、retrieve、subscribe/unsubscribe、retract、purge/delete、max-item pruning 已实现。
- 修复 inherited namespace 序列化，避免 payload 离开原 XML 上下文后失去 namespace。
- 加入 node/item/batch/payload 上限。
- outcast 即使面对 open model 也拒绝；订阅只能替当前 bare JID 操作。
- item replacement/retraction 在数据库 transaction 内检查 publisher/owner，阻止竞态下覆盖他人 item。

### 3.3 MUC、MAM、Roster 与存储提示

- MUC MAM 只允许当前 session 已加入的房间；结果 from 使用 room JID，支持稳定 RSM。
- 匿名房间拒绝 `with` sender 过滤，避免以 MAM 查询真实 JID。
- 已验证 OMEMO 群消息存档包含密文而没有客户端误附的明文 sibling。
- roster version 持久递增；匹配版本返回空 result；push 跨本机资源及 Redis 节点并携带版本。
- roster set 现在要求恰好一个 roster item，并拒绝 malformed/full-resource JID。
- standalone marker/chat state 默认不进入 MAM/离线队列；`store` 明确覆盖这一优化，`no-store` 始终优先，有其他语义 payload 时不误删。

### 3.4 联邦与 Direct TLS

- `_xmpps-server` 优先、`_xmpp-server` 回退；Direct TLS 意图存在但失败时不静默降级。
- C2S 仅配置 `xmpp-client` ALPN，S2S 仅配置 `xmpp-server`；未发送 ALPN 的兼容客户端可连接，协商出错误 ALPN 时拒绝。
- 修复 domain-only IQ routing、S2S 接收侧 IQ reply 未写回、失败写入时当前 envelope 丢失，以及关闭 federation 后 listener 提前返回导致主程序退出。
- 联邦队列返回真实入队/投递状态；错误日志不再打印完整 stanza envelope。

### 3.5 Redis 双节点（实验性）

- key 按 XMPP domain namespace；node/session lease 有 TTL 和 owner-checked refresh。
- full JID 使用原子 lease 抢占；另一活节点已持有同 resource 时返回 conflict，失败会回滚本机 session/metrics。
- 跨节点消息使用逐消息 ACK，而不是把 Redis publish 成功误当作 socket 投递成功。
- MUC nickname/capacity 原子预留，nickname 大小写不敏感；全局 occupant roster、消息、presence、leave、Carbons 和 roster push 已覆盖。
- listener/maintenance 遇到暂时 Redis 错误会记录 metric 并重连，而不是 panic 或永久停止。

### 3.6 防滥用与管理 API

- 注册策略从错误的 `base_work=0` 改为首次 burst 后真实平方台阶 PoW；message/report/appeal 保持不同严格度、指数 penalty、硬等待、上限及逐阶冷却。
- 清理完全冷却的 actor key 与 challenge issue key，阻止攻击者制造永久增长的内存 map。
- 后台关闭注册现在统一控制 HTTP、XEP-0077、XEP-0389、stream feature、discovery 与公开配置，消除协议绕过。
- session kick/panic disconnect 改为连接级 cancellation；TCP/WebSocket 主循环实际结束且不留下 SM resumable snapshot。
- 移除会直接改写 `.env`、允许注入且忽略失败的 `server_identity` 端点。服务名回归受校验的启动配置。
- destructive reset 不再递归删除 `UPLOAD_DIR`；只删除由 store 管理的 UUID/`.part` 对象，并保留无关文件/目录。
- broadcast 增加非空与 64 KiB 上限。

### 3.7 部署与证书

- 默认端口恢复为 5222/5223/5269/5270/8080，Compose 同步暴露 Direct TLS。
- bootstrap 管理密码只通过一次性 Compose overlay 挂载；改密后回到基础 Compose 并删除主机 bootstrap secret。
- production preflight 检查域名 SAN、30 天有效期、cert/key 匹配、非自签、非 SHA-1、RSA≥3072 或 ECDSA≥256，以及私钥 mode 0400/0600。
- `.gitignore` 覆盖 `.env`、证书/私钥、secret、数据库、日志、上传与备份；tracked-file 扫描未发现私钥材料。

## 5. 仍未解决的上线风险

1. **无独立安全审计/协议互操作认证**：当前审计由开发代理完成，不能视为第三方结论。
2. **PRECIS/IDNA 不完整**：特殊国际化 JID 的 canonicalization 与 confusable 风险仍在。
3. **S2S 无持久 outbox**：进程崩溃或长时间远端故障可能丢失内存队列。
4. **Redis 非生产基线**：Pub/Sub 非持久；SM、abuse、upload 与部分 admin/MUC 状态没有完整分布式语义。
5. **XML 输出仍大量使用字符串模板**：现有输入均应 escape，但未来新增漏 escape 的维护风险仍在。
6. **Archive retention/prefs 不完整**：个人/MUC archive 的运营保留与删除政策仍需实现。
7. **Generic PubSub/MUC 均非完整标准实现**：边界见 `XEP_MATRIX.md`，不可在宣传材料写 Full。
8. **证书与公网 DNS 尚需在真实域执行 production preflight**：本轮 runtime 用的是隔离测试 CA/短期证书。

## 6. 上线判定

建议将当前版本部署到只允许受控测试用户的 staging，使用正式 PostgreSQL、真实 TLS/DNS、外部监控与离机加密备份做一轮 soak test，并由 Gajim、Conversations 等至少两种独立客户端覆盖注册、双设备 OMEMO、MUC、MAM、上传和重连。公网正式开放前至少完成外部安全审计、archive retention 决策、S2S 丢失语义确认及生产证书 preflight。Redis 多节点应保持关闭，除非另行完成故障注入和共享对象存储设计。
